# 0122. An `f32` is a JS number, each result rounded with `Math.fround`

Status: Accepted. Extends [0064](0064-numbers.md) and [0086](0086-64-bit-integers.md).

## Context

rust-js had integers up to 64 bits and `f64`, and refused `f32`: it was the
type rustc's own tests most often stopped at (ADR 0089), and graphics,
audio and game code use it throughout. JS has one float, a double, and
`Math.fround(x)`, the `f32` nearest a double, which is what `Float32Array`
stores.

## Decision

**An `f32` is a JS number holding its value exactly, as every `f32` is a
double. Each result that may not be one is rounded to one with
`Math.fround`:**

| Rust | JS |
|---|---|
| `a + b`, `a - b`, `a * b`, `a / b` | `Math.fround(a + b)` and so on |
| `x.sqrt()`, `x.sin()`, `x.powf(y)`, … | `Math.fround(Math.sqrt(x))` and so on |
| `x.floor()`, `x.abs()`, `x.round()`, `x.min(y)`, `-x`, `a % b` | as for an `f64`: exact, so no `fround` |
| `0.1f32`, `f32::MAX` | `Math.fround(0.1)`, `Math.fround(3.4028235e38)`: its shortest digits, rounded; `1.5` where those are the number exactly |
| `x as f64`, `f64::from(x)` | `x` |
| `y as f32` of an `f64`, an `i32` or a `u32` | `Math.fround(y)` |
| `n as f32` of an `i64` or a `u64` | `$bigToF32(n)` |
| `x as i32` | `$f64ToInt(x, ..)`, saturating, as of an `f64` (ADR 0086) |
| `x.powi(n)` | `$powiF32(x, n)` |
| `{}`, `{:?}` | `$displayF32(x)`, `$debugF32(x)` |
| `{:.2}` | `$toFixed(x, 2)`, as of an `f64` |

- **`+`, `-`, `*`, `/` and `sqrt` are Rust's exactly**: a double holds the
  exact result of two `f32`s close enough that rounding it to an `f32`
  rounds it once, as a double has more than 2 × 24 + 2 bits. The library's
  others, `sin`, `exp`, `powf` and the rest, are JS's rounded, and may
  differ from Rust's in the last bit, as an `f64`'s may (ADR 0064).
- **An `i64` or a `u64` is rounded once, to 24 bits**: through an `f64`,
  `Math.fround(Number(n))`, it's rounded twice, and `2^60 + 2^36 + 1`,
  which is nearer `2^60 + 2^37`, becomes a tie that rounds to `2^60`.
- **`powi` is compiler-rt's `__powisf2`**, which rounds each product to an
  `f32`: `1.1f32.powi(9)` is `2.3579483`, and rounded once `2.357948`.
- **Shown as Rust shows it**: the fewest digits that read back as this
  `f32`, the nearest to it of those, a tie to the larger; `{}` never with
  an exponent, `{:?}` with one below `1e-4f32` and from `1e16f32`.
  `$f32Digits` tests a decimal against the `f32`'s rounding interval
  exactly, in BigInts: half as wide below a power of two, its ends this
  `f32`'s when its significand is even. A test through a double,
  `Math.fround(Number(text))`, rounds twice; it agreed on 300,000 values
  tried, which isn't a proof.
- **`{:.2}`** is the `f64` path's: the double holds the `f32` exactly, and
  `$toFixed` rounds an exact value as Rust does.
- **Still errors, each saying so:**
  - `s.parse::<f32>()`: Rust reads the digits to their nearest `f32`, and
    through an `f64` a near tie can be missed;
  - an `f32` in JSON, written or read: serde_json writes one with its own
    shortest digits, `0.1`, where a `Value` of it is an `f64`'s,
    `0.10000000149011612`;
  - `to_bits`, `from_bits` and `mul_add`.

## Why

- **It's the JS a person writes**: `Math.fround` is how JS code keeps a
  value an `f32`, and a `Float32Array` stores the same numbers.
- **It's exact where it's said to be**, and where it can't be, as for the
  library's functions, it's no less than an `f64` is.
- **Exact operations stay plain**: `Math.floor(x)` of an `f32` is one, so
  wrapping it would be noise.

## Alternatives

- **An `f32` as an `f64`, unrounded**: the simplest, and wrong at the
  first `0.1 + 0.2`, which Rust's `f32` makes `0.3`, and a double of the
  two `0.30000000447034836`, no `f32`.
- **A `Float32Array` cell for each value**: rounded by the store, but a
  value would be an object, and the JS nothing like a person's.

## Consequences

- `f32`, alone or in structs, `Vec`s, `Option`s, iterators' `sum` and
  `product`, sorts by `partial_cmp`, and generic code, compiles, compared
  with native Rust by the `f32` and `f32_digits` corpus cases: the latter
  shows every power of two an `f32` has, subnormals too, and 3,000 values
  of every size.
