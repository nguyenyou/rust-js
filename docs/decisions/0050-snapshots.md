# 0050. Snapshots of the generated JS, reviewed as diffs

Status: Accepted. Complements [0017](0017-differential-testing.md).

## Context

ADR 0017 tests behavior: the JS must compute what native Rust computes.
That can't see the other thing rust-js promises, which is JS that reads like
hand-written code. Two outputs can behave the same while one of them imports
a module it doesn't need, renames a prop to `editor$1`, or wraps a call in
an IIFE.

The tests pinned output with about 200 `toContain` checks, each of one
fragment. A change anywhere else went unseen. The traits change (ADR 0049)
dropped the import of a module used only through a `const`, and nothing
failed. Its playground check also passed, because it ran on a stale
`rust-js.wasm`.

## Decision

**Every example and fixture's generated JS is committed under
`test/snapshots/`, one folder per crate, as ordinary `.js` and `.jsx`
files.** `test/snapshots.test.ts` compiles each one with the native compiler
and compares it file by file: the same files, with the same text.

```text
examples/modules/lib.rs ──rust-js──► target/snapshots/modules/ ─┐
                                     test/snapshots/modules/   ─┴─► identical, or the diff
```

- **A change to the output fails with its diff**, and the file it's in. If
  the change is intended, `bun run bless` writes the new output as the
  snapshot, and `git diff` shows what the change did to the JS, for review.
- **Plain files, not a snapshot store.** They get syntax highlighting and
  ordinary diffs, and they can be opened or run. Bun's `toMatchSnapshot`
  keeps each output as a string in one `.snap` file.
- **No source maps.** They're long encoded strings that change with every
  edit. `emission.test.ts` checks them precisely.
- **Compiled from the repository's root**, with relative paths, so the
  headers (`Generated by rust-js from examples/fib.rs`) are the same on every
  machine.
- **The playground is a snapshot too, and `rust-js.wasm` is checked against
  it.** `test/playground.test.ts` compiles the playground with the wasm
  compiler, as the site does, and compares the result with the same
  snapshot. A wasm built from older code writes other JS, so the test fails
  and says to run `bun run wasm`. It never blesses: the snapshot is the
  native compiler's.

## Why

- **Behavior and form are both promises.** ADR 0017's oracle checks the
  first. A snapshot checks the second, and it checks the whole output, not
  the fragments someone thought to pin.
- **Review, not belief.** A snapshot isn't an expectation written by hand,
  which ADR 0017 rejects. It's the compiler's own output, and a change to it
  is shown to a person as a diff, like any other code change.
- **One snapshot, two compilers.** The same files check the native compiler
  and the WebAssembly one, so the playground can't drift from the CLI.

## Consequences

- A compiler change that changes output needs a bless in the same commit,
  and its diff is part of the review.
- The snapshots are about 50 files. Each new example or fixture adds a line
  to `test/snapshots.test.ts`.
- The `toContain` checks stay. They say *why* a fragment matters, which a
  snapshot doesn't.
