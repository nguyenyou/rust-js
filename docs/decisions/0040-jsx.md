# 0040. JSX: bindings whose `link_name` is a tag, printed as JSX in a `.jsx` file

Status: Accepted.

## Context

React code is JSX. For rust-js's React output (ADR 0041) to look
hand-written, it has to *be* JSX. A `jsx("div", { className: "hero" })` call
works but isn't what anyone writes. JSX has a second job as well: tools
recognize React code by it. Vite's React plugin gives Fast Refresh to `.jsx`
files, and to files that import `react/jsx-runtime`.

**ReScript** has JSX in its own syntax. Its ppx turns `<div className="a">`
into `ReactDOM.jsx("div", {className: "a"})`, with the props as a record
type. `<Counter />` becomes `React.jsx(Counter.make, props)`. With `"jsx":
{ "preserve": true }` (since v12), its printer turns those calls back into
JSX, in files with a `.jsx` suffix.

Rust has no JSX. A proc macro could parse it, but the playground's rustc
can't load proc macros (no dynamic libraries on WASI), so the syntax has to
be plain Rust. We chose typed builder methods, as Leptos and Sycamore also
offer:

```rust
button().r#type("button").class_name("counter").on_click(move |_| set_count.update(|c| c + 1)).children(("Count is ", count))
```

## Decision

**JSX comes from bindings (ADR 0039) whose `link_name` has JSX forms:**

| `link_name` | Rust | JSX |
|---|---|---|
| `<div>` | `div()` | `<div />` |
| `<>` | `fragment(children)` | `<>..</>` |
| `<react#StrictMode>` | `strict_mode(children)` | `<StrictMode>..</StrictMode>`, imported |
| `<*>` | `component(Counter, CounterProps { initial: 1 })` | `<Counter initial={1} />` |
| `prop className` | `element.class_name("hero")` | `className="hero"` |
| `prop` | `element.attr("aria-hidden", "true")` | `aria-hidden="true"` |

- **An element is built by one chain.** A `prop` binding's `this` must be an
  element being made, `div().class_name(..)`. Building one bit by bit through
  variables is an error that says so.
- **`children` is the element's children.** A tuple is several, so
  `("Count is ", count)` is `Count is {count}`. Anything else is one child,
  including a `Vec`, which React renders item by item. For `<*>`, a props
  struct's fields are attributes and its `children` field is the children.
  `()` means no props, and anything else is spread, `{...props}`.
- **A component's name must start with an uppercase letter.** JSX reads
  `<counter>` as a DOM element, and Fast Refresh only keeps a capitalized
  component's state.
- **A module with JSX is a `.jsx` file**, root included, and imports name it
  so. Others stay `.js`.

It's printed as by hand:

- A string child is text (`Count is `), and a string attribute is quoted
  (`className="hero"`). Either one becomes `{".."}` if it has `{}<>&`, a
  newline, or (for an attribute) a `"`. `true` is a bare attribute
  (`disabled`), and an `undefined` one (a `None`) is left out.
- Children that are all elements or expressions go on their own lines, one
  level deeper than the tag. A line with text in it stays whole, since JSX
  keeps spaces only within a line.
- oxc indents multi-line code by the statement it's in, not by where it sits
  in the JSX. So a handler or child that oxc would print on several lines
  goes in a `const` first, named after the attribute: `const onClick = () => {
  .. };`. This only happens when it can't change the order things run in. A
  handler that is one call stays inline as `() => setCount(1)`, because React
  ignores what a handler returns.

## Why

- **The output is the JSX a React user writes**, so tools treat it as theirs:
  Vite's plugin transforms it and adds Fast Refresh, and linters read it.
- **Each JSX part is a binding**, so rustc checks attribute names, their
  types and handler signatures with no JSX in the compiler's front end.
  rust-js only needs to know six forms.
- **ReScript's preserve mode made the same choice**, JSX in `.jsx` files, and
  reached it the same way: calls marked as JSX, printed back as JSX.

## Alternatives

- **`jsx(..)` calls** (`react/jsx-runtime`), as ReScript prints without
  preserve. Vite would still refresh them, but no one writes them.
- **A `rsx!`/`html!` macro.** It reads closer to JSX's shape, but
  `macro_rules!` has to munch tokens for it, which gives worse errors and
  needs a higher `recursion_limit` for a page-sized tree. It could later
  expand to the same bindings.
- **Elm-style `div([attrs], children)`.** Typed as well, but attributes go in
  an array.

## Consequences

- Building an element across statements (`let e = div(); e.class_name(..)`)
  is an error.
- Hoisted handlers are the one place the output differs in shape from the
  Rust, a `const` before the `return`.
